The remaining medium alert is the Sub Resource Integrity warning for the Cloudflare-injected Web Analytics script at `static.cloudflareinsights.com`. The low alerts concern third-party script inclusion, COEP/COOP response headers, and Unix timestamps embedded in a JavaScript bundle.

Those files are not part of the deployed Cloudflare Worker request path, but they must be reviewed before any legacy Node server is reused.

**This assessment is not a full production VAPT clearance.** CDN environment isolation was deliberately excluded at the user's request. Firebase Realtime Database rules and MongoDB Atlas account/network controls also require external verification.

## Findings and remediation

### VAPT-01: Staging API is coupled to the production CDN Worker

**Severity:** High  
**Status:** Open, intentionally excluded from this work

The staging API Worker uses the `dateme` CDN Worker in its production environment. The existing staging deployment workflow also synchronizes the `JWT_SECRET` to that production CDN Worker.

Impact:
- A staging deployment can affect the production CDN trust boundary.
- Staging and production do not have separate CDN signing credentials and service boundaries.

This finding was not remediated because CDN work was explicitly excluded. No CDN Worker source, B2 bucket policy, or CDN environment isolation change was made.

**Deployment side effect and current state:** The staging deployment workflow previously synchronized the staging API's `JWT_SECRET` to the production `dateme` CDN Worker. That production-secret write was removed from the staging workflow on 2026-11-05. The workflow now configures the API staging Worker secret only. However, the staging API still uses the production CDN endpoint and a shared signing trust boundary. This remaining coupling is intentionally open and excluded from this assessment.

### VAPT-02: Central Durable Object guard did not enforce all account restrictions

**Severity:** Medium  
**Status:** Fixed and deployed

Previously, the central Durable Object guard blocked accounts queued for deletion but did not centrally apply all account restrictions.

Remediation:
- Require `email_verified === true` for ordinary authenticated Durable Object operations.
- Apply the shared account restriction helper centrally, covering deletion-pending, deleted, permanently banned, and active temporary suspensions.
- Treat invalid suspension expiry timestamps as restricted.
- Add regression tests for active suspensions, invalid expiry values, unverified identities, and deletion-pending accounts.

### VAPT-03: Missing or overly broad browser security policy

**Severity:** Medium  
**Status:** Fixed in source and deployed

Added and validated:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Strict-Transport-Security: max-age=31536000`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy` limited to the app's camera, microphone, and geolocation requirements
- A restrictive Content Security Policy with explicit API, Firebase, CDN, Cloudflare Insights, and media sources
- Same-origin CORS policy for Pages static resources
- `Cross-Origin-Resource-Policy: same-origin`
- `Cross-Origin-Opener-Policy: same-origin-allow-popups`

The Pages deployment validator now checks the deployed CSP and cross-origin response headers. The CSP avoids broad scheme-wide source allowances. Inline style attributes remain permitted for the existing React UI; inline scripts and `unsafe-eval` are not allowed.

### VAPT-04: Support attachment CDN key validation rejected valid keys

**Severity:** Low, availability  
**Status:** Fixed in source and deployed

Corrected the support attachment key extension expression and added a regression test that verifies a valid ticket-scoped support attachment key produces the expected signed CDN claims.

### VAPT-05: Dependency exposure and tracked generated packages

**Status:** High/critical threshold remediated; low/moderate advisories remain

Remediation:

- Confirmed zero tracked `node_modules` paths remain.

- Upgraded Firebase Admin, Firebase Web SDK, React Router, and Sharp.
- Added compatible npm overrides for vulnerable transitive dependencies.
- Added Dependabot weekly updates.
- Added scheduled dependency audits.
- Added deployment-time `npm audit --audit-level=high` gates for Pages and Worker deployment.

Latest completed audit:
| Component | Result |
|---|---:|

| Legacy backend | 0 vulnerabilities |

The dependency remediation workflow passed frontend tests/build, backend regression tests, Worker tests, and the high/critical audit threshold.

**Dependabot activation limitation:** `.github/dependabot.yml` is present on `migrate-to-serverless`, but Dependabot reads its configuration from the repository's default branch. ### VAPT-06: MongoDB transport encryption

**Severity:** Medium  
**Status:** Fixed in source and deployed

The Worker MongoDB client now explicitly sets `tls: true`, enforcing TLS even if an operator supplies a standard `mongodb://` URI rather than an SRV URI.

MongoDB Atlas network allowlists, database user privileges, and production account settings were not independently inspected.

### VAPT-07: Firebase URL validation and input handling

**Severity:** Medium  
**Status:** Fixed in source and deployed

Remediation:
- Firebase Realtime Database URLs must use HTTPS and an actual `firebaseio.com` or `firebasedatabase.app` hostname. Suffix lookalikes and credential-bearing URLs are rejected.
- Admin email validation uses bounded parsing rather than a backtracking email regex.
- CDN base-path trimming no longer uses the flagged regular expression.
- External catalog titles have angle brackets stripped before being returned.
- Test-user generation uses cryptographic randomness.

Regression tests cover valid and invalid Firebase hostnames and email inputs.

### VAPT-08: Legacy Node/Express static-analysis findings

**Severity:** Requires legacy-code review  
**Status:** Open for legacy code only

The latest available CodeQL SARIF scan reports 84 findings, all outside the active `workers/` source. The artifact is from [workflow run 42055618953](https://github.com/Univercitysingle/dating-app/actions/runs/42055618953), which analyzed commit `062ab5aef908cdf78d519aa2e07c1005141632d7`:
- 39 log-injection findings across legacy controllers, middleware, `server.js`, and Firebase/Redis/Socket.IO services
- 16 tainted database-query findings in `adminReportsController.js`, `adminSupportTicketController.js`, `adminUsersController.js`, `matchesController.js`, `reportsController.js`, and `swipeController.js`
- 14 missing-rate-limiting findings, all located in test files (`tests/subscription.test.js` and `tests/supportTicket.test.js`)
- 8 tainted-format-string findings in legacy controllers and Redis/Socket.IO services
- 7 user-controlled-bypass findings in `authController.js` and `middleware/authentication.js`

The active Cloudflare Worker source had zero CodeQL findings in that scan. The legacy findings are not automatically confirmed exploitable. The database-query findings need manual review for MongoDB/NoSQL operator injection, and the authentication findings need manual review to distinguish validation-gated branches from genuine authorization bypasses. The 14 rate-limiting findings are in test harnesses, not deployed route handlers.

The scan predates the latest Worker header changes and the workflow cleanup. The CodeQL workflow was subsequently removed to satisfy the Cloudflare-only Actions requirement, so no newer CodeQL result is currently available. The old SARIF artifact is retained as historical evidence, not as a current scan of the branch head.

Remediation already completed in the legacy code:
- Removed Firebase token fragments from authentication logs.
- Removed sensitive IP/device metadata and full subscription objects from logs.
- Added an allowlist for admin sort fields.
- Replaced dynamic audit-map property writes with `Object.fromEntries`.

### VAPT-09: Firebase Realtime Database security rules

**Severity:** Not verified  
**Status:** External verification required

No Firebase Realtime Database rules file was found in the repository. The Firebase Admin SDK bypasses client RTDB rules, so server-side authorization must remain enforced by the application. The external RTDB rules and project IAM settings were not available for inspection.

Before enabling any client-side RTDB listener, verify rules enforce per-user/per-conversation membership and deny all unauthenticated access.
